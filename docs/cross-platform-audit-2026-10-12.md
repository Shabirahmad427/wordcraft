# Cross-platform architecture and regression audit

> **Last reviewed:** 2026-10-12 · **Last updated:** 2026-10-12 · **Change:** Phase 7I synthetic DOCX/PDF geometry corpus and proposed native matrix extension · **Status:** source and synthetic-test audit; no new Word 365 application comparison

Phase 7I adds [a cross-platform layout regression protocol](cross-platform-layout-regressions.md). All six local gates and native Apple Silicon GUI/CLI release builds passed; hosted results for this revision remain pending. A minimal fixture exposed an omitted clipping warning for a floating image anchored in a header. Shared layout now diagnoses it and the regression passes. PDF checks use an independent reader for media boxes and extracted text. They still lack a Word-generated reference pair and do not change the estimates below.

The document model, DOCX reader/writer, chart transactions, equation representation, bibliography handling, layout, raster rendering, PDF generation, and session recovery live in shared Rust crates (`doc`, `docx`, `layout`, `render`, `pdf`, `engine`). Platform differences are concentrated in the desktop app/UI and its printing and system adapters. The document crates contain no macOS-specific DOCX interpretation path. `cargo xtask layers` enforces the crate boundary, and `cargo xtask wasm` checks shared crates. This is an architecture finding, not native runtime certification.

The synthetic suite covers DOCX graph preservation, chart/XLSX transactions, equations, citations, pagination, PDF output, Undo/redo and failed-save recovery. The Document Regressions workflow runs reviewed two-page raster goldens and advisory 45/133-page workloads on Linux. This arc adds shared DOCX/engine tests on hosted Linux, macOS and Windows plus a Linux GUI/CLI release build and CLI smoke; all six jobs passed on `3a480b9`. Printing tests run on hosted Linux, macOS and Windows. Windows ARM64 has a package/install/run smoke workflow; the release workflow builds multiple targets, but a cross-build alone does not establish desktop behavior. The Word 365 corpus manifest exists, yet contains zero provenance-verified reference pairs. Private reference files must stay outside Git and remain unchanged.

## Shared-core improvement in this audit

Every `docx::write_as` result now passes the package graph/XML validator before returning. Previously only the guarded preservation path validated its final output. Export also rejects XML-forbidden model characters rather than silently omitting them; paragraph page/column break sentinels remain valid because they write as OOXML break elements. The regression uses a minimal synthetic paragraph containing U+0001 and checks every package flavor. This closes one output-integrity failure mode without a platform-specific branch. It does not prove Microsoft Word opens every generated package.

Local Apple Silicon verification: the DOCX integration suite and full `cargo xtask ci` passed all six gates (formatting, Clippy, tests, assets, layers, WASM). Native `cargo build --release --locked -p wordcraft -p wordcraft-cli` passed; both binaries reported version 0.6.1. The engine regression confirms a failed export leaves an existing destination and the in-memory document unchanged. A font-sensitive synthetic two-column footnote fixture was adjusted after it failed with native macOS font metrics; it now passes with both system fonts and bundled-only fonts.

Hosted [Document Regressions run 38320170798](https://github.com/Shabirahmad427/wordcraft/actions/runs/38320170798) passed all six jobs on `3a480b9`: native DOCX/engine integration tests on Ubuntu, macOS and Windows, Linux GUI/CLI release build plus CLI smoke, Linux visual regression, and advisory performance. [Packaging lint run 38320171307](https://github.com/Shabirahmad427/wordcraft/actions/runs/38320171307) also passed. These results do not establish Windows ARM64, macOS Intel, physical printing, or Word 365 application compatibility for this change.
