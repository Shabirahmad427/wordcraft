# Native save and workflow security notes

## File writes

`wordcraft_engine::io::save_path_with` serializes (and, when requested, encrypts) a document before it touches the destination. DOCX-family output is parsed from those generated bytes before commit. The native writer then creates a random sibling staging file with exclusive creation, writes all bytes, applies the prior regular file's basic permissions when replacing one, synchronizes the staged file, closes it, and renames it over the destination. On Unix it attempts to synchronize the containing directory after replacement; a failure is logged but does not turn an already committed replacement into a reported save failure. A symlink destination is rejected. Any error before replacement leaves the destination untouched; cleanup only targets the unique staging file owned by that save. PNG page export, UI/control screenshots and desktop preference writes use the same writer. Printing uses its own private, exclusively created temporary PDF file; the MCP/control key file is also created exclusively with owner-only Unix permissions.

This mitigates the former predictable `<document>.tmp` attack: a symlink or occupied entry at that name is never opened, truncated, renamed or removed. Exclusive creation prevents following a raced staging-path symlink; cryptographically random names make pre-creation races impractical. Concurrent saves stage independently; the last successful replacement wins. WordCraft does not lock documents or detect external edits.

Recovery snapshots use a separate private directory (mode `0700` on Unix), exclusive private files (mode `0600`), file synchronization and publication under immutable names. Incomplete `.partial` archives are not listed as snapshots. Recovery export uses a hard link to publish without overwriting an existing destination. These properties were reviewed in the existing implementation; this change does not replace that recovery design.

Focused native tests cover a malicious legacy temporary symlink, occupied temporary-file collision, destination symlink rejection, injected interrupted staging, concurrent saves, mode preservation and original-file preservation. DOCX save/reopen and package preservation remain covered by the existing engine and compatibility suites. Tests executed here ran on Linux. Windows replacement behavior, macOS/Linux filesystem variations, real permission-denied/disk-full faults, power-loss behavior, network filesystems, ACLs, ownership and extended attributes were not independently verified. Directory synchronization is Unix-only and best effort; file-data sync does not guarantee survival through power loss on every filesystem. Cleanup is best effort, so abrupt termination can leave a uniquely named staging file.

## GitHub Actions

The repository has four workflow call sites. The reusable workflows from `storytold/craft-common-actions` are pinned to reviewed commit `8f081ff5db115de44313c9db09415c359bf2ca01`, rather than `@main`. Their reviewed definitions use pinned SHAs for GitHub and third-party actions, define read-only permissions for FreeBSD, Windows ARM64 and packaging lint, and require write access for release publication. In this repository, release is triggered only from the `release` branch or an explicit maintainer dispatch; pull-request workflows do not receive release signing secrets, and there is no `pull_request_target` trigger.

The pinned reusable workflow definitions themselves invoke several `storytold/craft-common-actions/actions/...@main` composite actions. Pinning the workflow does not freeze those nested action refs. Eliminating that remaining mutability requires upstream changes or locally maintained copies and is not claimed complete here. Release signing credentials and `contents: write` are part of the release workflow's intended behavior and still warrant repository-environment protection and an independent permissions review.

This is a focused fix and workflow review, not an independent security audit or a claim of complete protection against a hostile same-user process, compromised runner, malicious filesystem, or compromised upstream organization.
