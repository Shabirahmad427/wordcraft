# Equation compatibility

WordCraft stores editable equations as a structured math tree and reads/writes Office Math Markup Language (OMML). The model and layout currently cover text and math styles, fractions, scripts, radicals, n-ary operators, delimiters, functions, limits, accents, bars, boxes, phantom nodes, aligned rows, matrices, display alignment and long display-equation wrapping. The Equation editor supports inline/display equations, structure insertion, symbols, UnicodeMath-like input, LaTeX-like input, linear/professional conversion, automatic display numbering and keyboard navigation.

On DOCX import, WordCraft retains each equation's original `m:oMath` XML. If the reader encounters an OMML element it does not model, it marks that equation as unsupported. The original XML remains available for DOCX output, while editing commands fail with a preservation message instead of clearing the source XML and silently dropping the structure. Supported constructs remain editable and are serialized from the current math tree after edits.

For Word output, automatic `#` markers become explicit parenthesized numbers in OMML, and the marker is removed from printable content. On import, WordCraft restores a marker only when a trailing parenthesized integer matches the next expected document-order number. This keeps numbering editable and restores WordCraft's right-aligned numbered-row layout. Exact raster tests cover two consecutive numbered equations through Undo, recovery, DOCX save/reopen and PDF export. This ordered-pattern inference is conservative but can still misidentify a deliberately parenthesized terminal integer in an equation array.

The Cross-reference command can target Equation captions. Those use Word-compatible `SEQ Equation` and bookmarked `REF` fields; updating fields refreshes their numbers, and a missing target clears its cached result rather than showing a stale number. References to equations numbered only by OMML `#` markers are not yet linked to those equation objects. No stable equation identity or section-based numbering is represented in the current model, so renumbering follows document order and numbering remains continuous. Section-number formats such as (2.4), target navigation from an OMML number, and a full Equation cross-reference dialog remain open work.

The import guard does not certify preservation of arbitrary extension attributes, unknown properties inside recognized property containers, all revision semantics, or every OMML version. Unsupported LaTeX commands may remain literal text; the parser is a convenient input format, not a complete TeX implementation. Equations that exceed the tested layout model and independent Word-rendered comparison remain open work.

Tests cover structured equation parsing/editing, representative OMML read/write, unknown-node protection, display numbering and long display-equation wrapping. These are internal regression tests; no Microsoft Word reference output was used for this work.
